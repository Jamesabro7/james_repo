# Табель учёта рабочего времени — выгрузка за сентябрь 2026

Источник: PDF-отчёт «Табель — Все записи» (период 01.09.2026 — 30.09.2026, сформирован 29.09.2026 19:00, 720 записей, 37 страниц).
Извлечение выполнено программно (pdfplumber), нумерация `#` сплошная 1–720, потерь строк нет.

## Файлы

| Файл | Назначение |
|---|---|
| `tabel_2026-09.csv` | Точная копия таблицы из PDF: те же колонки, те же значения (включая «—»). UTF-8 с BOM, разделитель `,`. |
| `tabel_2026-09_normalized.csv` | Та же таблица в машиночитаемом виде: латинские имена колонок, дата ISO, пустые значения вместо «—». Основа для ТЗ разработчикам. |

## Особенности данных, которые нужно учесть в ТЗ

1. **Пустые значения** в исходнике обозначены символом «—» (em dash, U+2014), а не пустой ячейкой. В normalized-версии заменены на пустую строку.
2. **`hours` = 0.00 при наличии входа и выхода** — 55 записей: в 46 случаях вход и выход совпадают минута в минуту, в 9 случаях разница в одну минуту. Фактически это одна отметка (сотрудник не отметился на выходе, либо отметился дважды подряд). Правило расчёта часов в исходной системе не документировано.
3. **`hours` = 0.00 при отсутствии выхода** — 245 записей (`Не отметился на выходе`, `Сейчас на смене`). Отработанное время не рассчитывается без отметки выхода.
4. **Ночная смена** учитывается двумя записями: вход вечером (`Ночная смена (выход утром)`) и выход на следующий день (`Это ВЫХОД с ночной смены`), обе с `hours` = 0.00. Часы за ночную смену в отчёте не считаются.
5. **Латиница в ФИО**: «Cамадов Анвар» — первая буква латинская `C` (U+0043), не кириллическая `С`. 13 записей. При джойне со справочником сотрудников будет расхождение.
6. **Дублирование имени**: «Пулатов Икром Илхомович Икром» — артефакт исходной системы (имя повторено).
7. **Логика статуса `Опоздание` не сводится к порогу по времени входа.** Все 115 записей `Опоздание` имеют `time_in` от 09:01, но при этом 314 записей `На месте` тоже имеют вход в 09:00 и позже (118 из них — после 09:30). Значит, статус зависит от чего-то ещё (индивидуальный график, льготы, ручная корректировка). Правило нужно запросить у владельца системы до постановки ТЗ.
8. **Идентификаторов нет**: ни табельного номера сотрудника, ни кода отдела. Для интеграции потребуется справочник сотрудников и отделов с ключами.
9. **Порядок строк**: отчёт отсортирован по дате по убыванию (29.09 → 02.09), внутри даты — по времени входа по убыванию.
10. **Уникальность**: пара (`employee`, `date`) уникальна во всех 720 строках — можно использовать как составной ключ.
