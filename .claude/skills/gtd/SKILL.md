# GTD — система личных задач

## Структура файлов

Все списки живут в папке `gtd/` (в проекте или рабочей папке пользователя):

- `inbox.md` — всё входящее, неразобранное;
- `next-actions.md` — конкретные следующие действия, сгруппированные по
  контекстам (@компьютер, @офис, @звонки, @поручить);
- `projects.md` — проекты (всё, что требует больше одного действия), у каждого
  проекта: желаемый результат + одно следующее действие;
- `waiting.md` — делегированное и ожидаемое от других (кто, что, с какой даты);
- `someday.md` — «когда-нибудь/может быть»;
- `calendar.md` — только жёсткие обязательства с датой/временем.

Если файлов нет — создай при первом использовании.

## Разбор инбокса (clarify)

Для каждого пункта задай по порядку:

1. **Это требует действия?** Нет → мусор, справочное (в базу знаний) или
   someday.md.
2. **Действий больше одного?** Да → это проект: запиши в projects.md результат
   и первое действие.
3. **Займёт меньше 2 минут?** Да → предложи сделать сразу.
4. **Это должен делать пользователь?** Нет → в waiting.md с именем и датой.
5. Иначе → в next-actions.md с контекстом, либо в calendar.md, если привязано
   к дате.

Действие формулируй как конкретный физический шаг: не «отчёт», а «запросить
у Х данные за июнь письмом».

## Еженедельный обзор

По запросу «обзор недели» пройди чек-лист: инбокс до нуля → просмотреть
projects.md (у каждого проекта есть следующее действие?) → waiting.md
(что зависло, кому напомнить?) → calendar.md на 2 недели вперёд →
someday.md (что пора активировать?). В конце — краткая сводка: сколько
проектов, сколько зависших ожиданий, топ-3 приоритета на неделю.

## Ответ на «что делать дальше»

Спроси (или определи из контекста) доступное время и контекст, затем предложи
2–3 действия из next-actions.md, подходящие по времени/контексту, начиная
с привязанных к дедлайнам.
