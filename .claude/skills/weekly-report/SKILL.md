# Еженедельный отчёт

## Источники данных (по порядку)

1. `gtd/` — если файлы есть: завершённые и активные проекты, зависшие
   ожидания из waiting.md.
2. Файлы мониторинга/данные, приложенные к запросу.
3. Если данных мало — задай пользователю максимум 3 вопроса одним сообщением:
   главные результаты недели, главные проблемы, приоритеты следующей недели.
   Не растягивай сбор на много итераций.

## Структура отчёта

```
ЕЖЕНЕДЕЛЬНЫЙ ОТЧЁТ
[Ф.И.О. / подразделение] · [период: дд.мм–дд.мм.гггг]

1. ВЫПОЛНЕНО (3–7 пунктов)
   — результат, а не процесс: не «работал над дашбордом»,
     а «дашборд обновлён данными за июнь, разослан руководству»

2. В РАБОТЕ (с % готовности или этапом и сроком завершения)

3. ПРОБЛЕМЫ / ТРЕБУЕТСЯ РЕШЕНИЕ РУКОВОДСТВА
   — только то, что требует внимания адресата: зависшие ответы других
     ведомств (из waiting.md), риски сроков, нужные ресурсы

4. ПЛАН НА СЛЕДУЮЩУЮ НЕДЕЛЮ (топ-3–5, с датами)
```

## Правила

- Весь отчёт — не длиннее одной страницы. Руководитель читает 60 секунд.
- Каждый пункт — законченный факт с числом или датой, где возможно.
- Раздел 3 — самый важный: если он пустой, спроси пользователя, точно ли
  нет зависших вопросов (проверь waiting.md на просроченные).
- Язык и тон — деловой, без канцелярита сверх необходимого; на узбекском —
  вычитка по uzbek-grammar.
- По запросу оформи в Word (docx, стандарты оформления — gov-doc-copywriter)
  или короткое сообщение для Telegram.

## После отчёта

Предложи обновить GTD: перенести выполненное в архив, обновить статусы
проектов, добавить план недели в next-actions.md.
